# 🐧 Objective 110.2: Thiết Lập Bảo Mật Host & TCP Wrappers (LPI 102-500) - Bản Chất Hệ Thống & Thực Chiến DevOps

> 💡 **Bản chất 1 câu**: Tăng cường bảo mật đăng nhập với Shadow Passwords (`/etc/shadow`), siêu daemon `inetd/xinetd`, tường lửa ứng dụng `TCP Wrappers` (`/etc/hosts.allow`, `/etc/hosts.deny`) và vô hiệu hóa dịch vụ dư thừa.  
> 🎯 **Trọng tâm phỏng vấn DevOps**: Mã hóa /etc/shadow, siêu daemon xinetd, TCP Wrappers (/etc/hosts.allow, /etc/hosts.deny, libwrap.so), vô hiệu hóa daemon rác.

---

## 1. 🧠 Hình Hình Dung Nhanh (Intuitive Mindset)

TCP Wrappers như bảo vệ gác cổng riêng cho từng căn hộ: Trước khi cho ai đó kết nối vào dịch vụ SSH hoặc FTP, bảo vệ giở sổ `/etc/hosts.allow` ra kiểm tra IP, nếu không có trong danh sách thì đối chiếu `/etc/hosts.deny` để từ chối ngay lập tức.

---

## 2. 📚 Lý Thuyết Chuyên Sâu & Bản Chất Hệ Thống (Under The Hood Mechanics - LPI Official 101 & 102)

### 2.1 Bản Chất Các Lớp Bảo Mật Host Trên Linux

1. **Shadow Passwords (`/etc/shadow`)**:
   - Thời kỳ đầu Linux lưu password hash trực tiếp trong `/etc/passwd` (ai cũng đọc được -> dễ bị offline brute-force).
   - Kiến trúc Shadow chuyển password hash sang `/etc/shadow` có quyền `-rw-r-----` thuộc `root:shadow`, chỉ root mới đọc được.
   - Các công cụ quản lý: `pwconv` (bật shadow), `pwunconv` (tắt shadow).

2. **Siêu Daemon (Super-Daemons: `inetd` & `xinetd`)**:
   - Thay vì chạy 50 daemon dịch vụ nhỏ tốn RAM lắng nghe 50 port, Linux dùng 1 Super-daemon (`xinetd`) duy nhất lắng nghe tất cả các port. Khi có connection tới port 21, `xinetd` mới khởi chạy `ftpd` để xử lý rồi tắt đi.

3. **Tường Lửa Ứng Dụng TCP Wrappers (`libwrap.so`)**:
   - Dịch vụ được biên dịch cùng thư viện `libwrap.so` (như SSHD) sẽ tự động kiểm tra quyền truy cập IP qua 2 file:
     1. `/etc/hosts.allow` (Được ưu tiên kiểm tra ĐẦU TIÊN).
     2. `/etc/hosts.deny` (Nếu không khớp trong hosts.allow thì kiểm tra tại đây).
   - Cú pháp: `daemon_list : client_list [: option]`.
   - Ví dụ chặn tất cả SSH ngoại trừ IP công ty `203.162.1.50`:
     - `/etc/hosts.allow`: `sshd : 203.162.1.50`
     - `/etc/hosts.deny`: `sshd : ALL`

4. **Tắt Các Dịch Vụ Rác Không Sử Dụng (Disabling Unnecessary Services)**:
   - Kiểm tra các port đang mở: `ss -tulpn` hoặc `nmap localhost`.
   - Tắt dịch vụ rác: `sudo systemctl disable --now telnet.socket rsh.socket`.

## 4. 🛠 Thao Tác Thực Chiến & Kịch Bản DevOps (Real-World Scenarios)

### 🛠 Các lệnh thực hành gõ là ăn ngay:
```bash
# 1. Cấu hình TCP Wrappers chỉ cho phép IP công ty kết nối SSH:
cat << 'EOF' | sudo tee /etc/hosts.allow
sshd : 203.162.1.50 10.0.0.0/24
EOF

cat << 'EOF' | sudo tee /etc/hosts.deny
sshd : ALL
EOF
```

### 🚀 Kịch bản xử lý sự cố thực tế khi đi làm:
Khóa bảo mật Host Server cấp tốc:
# Tắt các dịch vụ truyền file không mã hóa nguy hiểm:
sudo systemctl stop telnet.socket rsh.socket vsftpd 2>/dev/null || true
sudo systemctl disable telnet.socket rsh.socket vsftpd 2>/dev/null || true

## 5. 🚀 Bộ Câu Hỏi Phỏng Vấn DevOps Thực Tế (Interview Q&A)

> **Q: File nào lưu trữ Password Hash riêng biệt chỉ có quyền Root truy cập?**  
> **A**: File `/etc/shadow`.

> **Q: Thứ tự ưu tiên kiểm tra quyền kết nối IP của TCP Wrappers như thế nào?**  
> **A**: Hệ thống kiểm tra `/etc/hosts.allow` TRƯỚC. Nếu khớp thì ALLOW ngay. Nếu không khớp mới kiểm tra `/etc/hosts.deny`.

> **Q: Làm sao biết một dịch vụ thực thi (như sshd) có hỗ trợ TCP Wrappers hay không?**  
> **A**: Dùng lệnh `ldd /usr/sbin/sshd | grep libwrap`.
