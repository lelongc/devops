# 🐧 Objective 110.1: Quản Trị Bảo Mật Hệ Thống & Sudo Audit (LPI 102-500) - Bản Chất Hệ Thống & Thực Chiến DevOps

> 💡 **Bản chất 1 câu**: Rà soát lỗ hổng SUID/SGID, quản lý chính sách tuổi mật khẩu (`chage`), tăng giới hạn tài nguyên (`ulimit`/`limits.conf`), cấu hình `sudo` với `visudo` và quản lý người dùng đang đăng nhập (`w`, `who`, `last`).  
> 🎯 **Trọng tâm phỏng vấn DevOps**: Audit SUID/SGID (find / -perm -4000), chage (password aging), ulimit / limits.conf (nofile/nproc), cấu hình sudo (/etc/sudoers, visudo), giám sát user (w, who, last, pkill).

## 1. 🧠 Hình Hình Dung Nhanh (Intuitive Mindset)

Quản trị bảo mật Linux Server như quản lý tòa nhà văn phòng: Rà soát cổng thoát hiểm (SUID Audit), bắt buộc đổi thẻ từ theo định kỳ (chage), cài đặt số lượng người tối đa trong thang máy (ulimit) và cấp quyền truy cập phòng VIP bằng sổ đăng ký bảo vệ (sudoers).

## 2. 📚 Lý Thuyết Chuyên Sâu & Bản Chất Hệ Thống (Under The Hood Mechanics - LPI Official 101 & 102)

### 2.1 Các Tác Vụ Quản Trị Bảo Mật Cốt Lõi (Security Administration)

1. **Rà Soát File SUID / SGID Nguy Hiểm**:
   - File SUID (Bit 4000) thực thi với quyền của Owner (root). Nếu file thực thi bị khai thác chèn mã độc, Hacker có thể chiếm quyền Root lập tức.
   - Lệnh audit: `find / -perm -4000 -type f 2>/dev/null` (SUID) hoặc `find / -perm -2000 -type f 2>/dev/null` (SGID).

2. **Quản Lý Tuổi Thọ Mật Khẩu (Password Aging Policy)**:
   - Xem thông tin tuổi mật khẩu: `chage -l username`.
   - Các tham số chính:
     - `-M 90`: Mật khẩu hết hạn sau 90 ngày.
     - `-m 7`: Tối thiểu 7 ngày mới được đổi pass lại.
     - `-W 14`: Cảnh báo trước 14 ngày khi pass sắp hết hạn.
     - `-E YYYY-MM-DD`: Hết hạn tài khoản vào ngày chỉ định.

3. **Giới Hạn Tài Nguyên Tiến Trình (Process Resource Limits - ulimit)**:
   - Cấu hình Soft & Hard limit trong `/etc/security/limits.conf`.
   - Các chỉ số quan trọng cho Server chịu tải lớn (Nginx, Node.js, Database):
     - `nofile`: Số lượng File Descriptors mở tối đa (mặc định 1024 -> tăng lên 65535).
     - `nproc`: Số lượng tiến trình tối đa một user được tạo.

4. **Cấu Hình Cấp Quyền Sudo An Toàn (`/etc/sudoers` & `visudo`)**:
   - BẮT BUỘC dùng lệnh `visudo` để chỉnh sửa `/etc/sudoers` (tự động kiểm tra cú pháp tránh khóa mất quyền root).
   - Cú pháp: `user HOST=(RUNAS_USER:RUNAS_GROUP) COMMANDS`.
   - Cho phép nhóm devops chạy sudo không cần nhập pass: `%devops ALL=(ALL) NOPASSWD: ALL`.

5. **Giám Sát & Ngắt Phiên Đăng Nhập Người Dùng (Session Audit)**:
   - `w` / `who`: Xem ai đang đăng nhập và đang chạy lệnh gì.
   - `last`: Xem lịch sử đăng nhập vào hệ thống từ `/var/log/wtmp`.
   - `pkill -u username` hoặc `pkill -9 -t pts/0`: Đá phiên làm việc rủi ro ra khỏi Server.

## 3. ⚡ Bảng Tra Cứu Câu Lệnh Thực Hành (CLI Command Reference)

| Câu lệnh | Tham số (Options/Flags) | Giải thích ý nghĩa chi tiết | Ví dụ thực tế trong DevOps |
| :--- | :--- | :--- | :--- |
| **`visudo`** | `Mở file /etc/sudoers sửa quyền sudo an toàn có check syntax` | Không | `sudo visudo` |
| **`chage`** | `Xem và thiết lập chính sách tuổi thọ mật khẩu` | -l, -M, -W | `sudo chage -M 90 devops` |
| **`ulimit`** | `Xem và đặt giới hạn tài nguyên Shell (file/process)` | -a, -n, -u | `ulimit -n 65535` |
| **`w / who / last`** | `Kiểm tra danh sách và lịch sử người dùng đăng nhập` | Không | `w` |
| **`pkill`** | `Hủy các tiến trình hoặc phiên đăng nhập của user` | -9 -u, -t | `sudo pkill -9 -u hacker` |

## 4. 🛠 Thao Tác Thực Chiến & Kịch Bản DevOps (Real-World Scenarios)

### 🛠 Các lệnh thực hành gõ là ăn ngay:
```bash
# 1. Tăng ulimit nofile cho Nginx/Docker trong /etc/security/limits.conf:
cat << 'EOF' | sudo tee -a /etc/security/limits.conf
* soft nofile 65535
* hard nofile 65535
* soft nproc 65535
* hard nproc 65535
EOF

# 2. Cấp quyền sudo NOPASSWD cho group devops qua visudo:
echo '%devops ALL=(ALL) NOPASSWD: ALL' | sudo tee /etc/sudoers.d/devops
```

### 🚀 Kịch bản xử lý sự cố thực tế khi đi làm:
Rà soát sự cố nghi vấn bị xâm nhập hệ thống:
# 1. Kiểm tra người dùng đang đăng nhập:
w
# 2. Xem lịch sử login:
last | head -n 20
# 3. Đá phiên đăng nhập rủi ro tại pts/1:
sudo pkill -9 -t pts/1

## 5. 🚀 Bộ Câu Hỏi Phỏng Vấn DevOps Thực Tế (Interview Q&A)

> **Q: Tại sao BẮT BUỘC phải dùng lệnh `visudo` thay vì sửa trực tiếp `/etc/sudoers`?**  
> **A**: Vì `visudo` tự động kiểm tra lỗi cú pháp (Syntax Check) trước khi lưu. Sửa lỗi trực tiếp `/etc/sudoers` có thể làm hỏng quyền sudo làm khóa hoàn toàn Server.

> **Q: Lệnh nào đặt số lượng File Descriptors mở tối đa lên 65535 cho phiên làm việc hiện tại?**  
> **A**: Lệnh `ulimit -n 65535`.

> **Q: Lệnh nào audit danh sách các file mang quyền SUID trên hệ thống?**  
> **A**: Lệnh `find / -perm -4000 -type f 2>/dev/null`.
