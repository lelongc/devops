## 2. 📚 Lý Thuyết Chuyên Sâu & Bản Chất Hệ Thống (Under The Hood Mechanics)

### 2.1 Bản Chất File Descriptors (FD) & Redirection
Mỗi tiến trình Linux luôn mở sẵn 3 File Descriptors mặc định:
- `0`: STDIN (Standard Input - Bàn phím).
- `1`: STDOUT (Standard Output - Màn hình).
- `2`: STDERR (Standard Error - Màn hình hiển thị lỗi).
System call `dup2()` được dùng để trỏ FD 1 hoặc FD 2 sang file đĩa. `2>&1` ép luồng lỗi 2 trỏ vào cùng vị trí với luồng 1.
Lệnh `pipe` (`|`) kết nối STDOUT của tiến trình A trực tiếp sang STDIN của tiến trình B qua bộ đệm Kernel 64KB.

## 3. ⚡ Bảng Tra Cứu Câu Lệnh Thực Hành (CLI Command Reference)

| Câu lệnh | Tham số (Options/Flags) | Giải thích ý nghĩa chi tiết | Ví dụ thực tế trong DevOps |
| :--- | :--- | :--- | :--- |
| **`>`** | `Ghi đè Standard Output vào file` | Không | `echo 'hello' > file.txt` |
| **`>>`** | `Ghi nối tiếp Standard Output vào file` | Không | `echo 'log' >> app.log` |
| **`2>`** | `Điều hướng riêng luồng lỗi Standard Error` | Không | `cmd 2> err.log` |
| **`tee`** | `Vừa in ra màn hình vừa ghi vào file` | -a | `echo 'data' | tee -a app.log` |

## 4. 🛠 Thao Tác Thực Chiến & Kịch Bản DevOps (Real-World Scenarios)

### 🛠 Các lệnh thực hành gõ là ăn ngay:
```bash
# Gom cả output lẫn error vào file log:
./deploy.sh > build.log 2>&1

# Vừa xem log trên terminal vừa lưu file:
./run.sh | tee -a run.log
```

### 🚀 Kịch bản xử lý sự cố thực tế khi đi làm:
Lưu log build CI/CD:
./build.sh > output.log 2>&1

## 5. 🚀 Bộ Câu Hỏi Phỏng Vấn DevOps Thực Tế (Interview Q&A)

> **Q: Số đại diện cho luồng Standard Error (STDERR) là bao nhiêu?**  
> **A**: Là số `2`.

> **Q: Làm sao vừa hiển thị output ra màn hình vừa ghi nối tiếp vào file log?**  
> **A**: Sử dụng lệnh `| tee -a file.log`.
