## 2. 📚 Lý Thuyết Chuyên Sâu & Bản Chất Hệ Thống (Under The Hood Mechanics)

### 2.1 Bản Chất Quản Lý Lưu Trữ LVM (Logical Volume Manager)
LVM là lớp trừu tượng hóa (Abstraction Layer) nằm giữa hệ thống tệp (Filesystem) và đĩa cứng vật lý:
1. **Physical Volume (PV)**: Khởi tạo các partition hoặc đĩa cứng thật (`pvcreate /dev/sdb`).
2. **Volume Group (VG)**: Gom các PV thành một vùng dung lượng dùng chung (`vgcreate vg_data /dev/sdb /dev/sdc`). Dữ liệu được chia thành các khối **PE (Physical Extents)** mặc định 4MB.
3. **Logical Volume (LV)**: Cắt dung lượng từ VG tạo thành các phân đĩa ảo (`lvcreate`).
- **Tăng dung lượng online**: `lvextend -L +20G -r /dev/vg/lv_var`. Cờ `-r` tự động gọi `resize2fs` (Ext4) hoặc `xfs_growfs` (XFS) để mở rộng filesystem trực tiếp mà không cần unmount.

## 3. ⚡ Bảng Tra Cứu Câu Lệnh Thực Hành (CLI Command Reference)

| Câu lệnh | Tham số (Options/Flags) | Giải thích ý nghĩa chi tiết | Ví dụ thực tế trong DevOps |
| :--- | :--- | :--- | :--- |
| **`pvcreate`** | `Tạo Physical Volume` | Path | `pvcreate /dev/sdb` |
| **`vgcreate`** | `Tạo Volume Group gom các PV` | Name Path | `vgcreate vg_data /dev/sdb` |
| **`lvextend`** | `Tăng dung lượng đĩa ảo LV online` | -L, -r | `lvextend -L +20G -r /dev/vg_data/lv_var` |

## 4. 🛠 Thao Tác Thực Chiến & Kịch Bản DevOps (Real-World Scenarios)

### 🛠 Các lệnh thực hành gõ là ăn ngay:
```bash
# Mở rộng thêm 50GB cho phân đĩa /var/lib/docker đang bị đầy:
sudo lvextend -L +50G -r /dev/mapper/vg_system-lv_var
```

### 🚀 Kịch bản xử lý sự cố thực tế khi đi làm:
Xử lý sự cố /var/lib/docker 100% full đĩa trên K8s Node:
sudo lvextend -L +50G -r /dev/mapper/vg_system-lv_var

## 5. 🚀 Bộ Câu Hỏi Phỏng Vấn DevOps Thực Tế (Interview Q&A)

> **Q: Làm sao tăng dung lượng đĩa LVM online không cần restart?**  
> **A**: Dùng `sudo lvextend -L +20G -r /dev/vg/lv_name` (cờ `-r` tự động resize filesystem).

> **Q: Thư mục nào cần cân nhắc tách phân đĩa riêng?**  
> **A**: Thư mục `/var` (chứa log và dữ liệu Docker) dễ làm đầy đĩa.
