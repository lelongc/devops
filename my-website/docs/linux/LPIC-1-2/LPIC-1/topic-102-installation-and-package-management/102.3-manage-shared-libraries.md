> 💡 **Bản chất 1 câu**: Chương trình Linux dùng chung các file thư viện động `.so`, kiểm tra phụ thuộc bằng `ldd` và cập nhật bộ đệm bằng `ldconfig`.  
> 🎯 **Trọng tâm phỏng vấn DevOps**: Lệnh ldd kiểm tra thiếu file .so, bộ đệm ld.so.cache, biến LD_LIBRARY_PATH.

## 2. 📚 Lý Thuyết Chuyên Sâu & Bản Chất Hệ Thống (Under The Hood Mechanics)

### 2.1 Bản Chất Liên Kết Thư Viện Động (Dynamic Linking)
- Các file `.so` (Shared Object) nằm tại `/lib`, `/usr/lib`, `/lib64`.
- Trình liên kết động `ld-linux.so` đọc file bộ đệm `/etc/ld.so.cache` (được tạo ra bởi lệnh `ldconfig` dựa trên `/etc/ld.so.conf`).
- `ldd /path/to/binary`: Kiểm tra các file `.so` phụ thuộc và đường dẫn giải mã.
- `export LD_LIBRARY_PATH=/path`: Thêm đường dẫn tìm file `.so` ưu tiên cho ứng dụng.

## 3. ⚡ Bảng Tra Cứu Câu Lệnh Thực Hành (CLI Command Reference)

| Câu lệnh | Tham số (Options/Flags) | Giải thích ý nghĩa chi tiết | Ví dụ thực tế trong DevOps |
| :--- | :--- | :--- | :--- |
| **`ldd`** | `Kiểm tra file binary cần những file .so nào` | Không | `ldd /usr/bin/nginx` |
| **`ldconfig`** | `Cập nhật lại bộ đệm thư viện ld.so.cache` | -v | `sudo ldconfig` |

## 4. 🛠 Thao Tác Thực Chiến & Kịch Bản DevOps (Real-World Scenarios)

### 🛠 Các lệnh thực hành gõ là ăn ngay:
```bash
# Kiểm tra Nginx có bị thiếu thư viện .so nào không:
ldd /usr/bin/nginx

# Thêm thư mục chứa file .so tạm thời:
export LD_LIBRARY_PATH=/opt/custom_lib:$LD_LIBRARY_PATH
```

### 🚀 Kịch bản xử lý sự cố thực tế khi đi làm:
Debug lỗi missing library trong Docker Container:
ldd /app/main

## 5. 🚀 Bộ Câu Hỏi Phỏng Vấn DevOps Thực Tế (Interview Q&A)

> **Q: Lệnh nào kiểm tra một file thực thi có bị thiếu thư viện .so không?**  
> **A**: Lệnh `ldd /path/to/binary`.

> **Q: Làm sao chỉ định đường dẫn tìm file .so tạm thời?**  
> **A**: Sử dụng biến môi trường `export LD_LIBRARY_PATH=/path`.
