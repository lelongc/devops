# 🐧 Objective 207.3: Cấu Hình DNSSEC & Advanced DNS Views - Bản Chất Hệ Thống LPIC-2 & Thực Chiến DevOps

> 💡 **Bản chất 1 câu**: Triển khai chuẩn bảo mật DNSSEC chống nhiễm độc cache (DNS Spoofing), ký số Zone bằng `dnssec-signzone` và cấu hình DNS Views (Split-horizon DNS).  
> 🎯 **Trọng tâm phỏng vấn Senior DevOps / SysAdmin**: DNSSEC (KSK Key Signing Key, ZSK Zone Signing Key, RRSIG, DNSKEY, DS record), dnssec-keygen, dnssec-signzone, Split-Horizon DNS Views (view option trong named.conf).

---

## 1. 🧠 Hình Hình Dung Nhanh (Intuitive Mindset)

Split-Horizon DNS Views như người phân loại khách hàng: Khách bên trong công ty hỏi IP server `app.company.com` thì trả về IP nội bộ `10.0.0.50`. Khách ngoài Internet hỏi thì trả về IP public `203.162.1.50`.

---

## 2. 📚 Lý Thuyết Chuyên Sâu & Bản Chất Hệ Thống (Under The Hood Mechanics - LPIC-2 Official Study Guide)

### 2.1 Bản Chất Của DNSSEC & Split-Horizon DNS Views
1. **Bảo Mật Chống Giả Mạo Bằng DNSSEC**:
   - DNSSEC sử dụng chữ ký số mã hóa bất đối xứng để xác thực tính toàn vẹn của bản ghi:
     - **ZSK (Zone Signing Key)**: Ký trực tiếp các bản ghi RRset trong Zone -> Tạo bản ghi **RRSIG**.
     - **KSK (Key Signing Key)**: Ký lên ZSK và tạo bản ghi **DS (Delegation Signer)** để gửi lên Registrar cấp cao hơn.
2. **Cấu Hình DNS Views (Split-Horizon / Split-Brain DNS)**:
   - Cho phép BIND 9 trả về các câu trả lời DNS khác nhau tùy thuộc vào địa chỉ IP của Client truy vấn!
   - Sử dụng khối `view "internal" { match-clients { 10.0.0.0/8; }; ... };` và `view "external" { match-clients { any; }; ... };`.

## 3. ⚡ Bảng Tra Cứu Câu Lệnh & Cấu Hình Thực Hành (CLI Reference)

| Câu lệnh / Component | Tham số / Option | Giải thích ý nghĩa chi tiết | Ví dụ thực tế trong DevOps / SysAdmin |
| :--- | :--- | :--- | :--- |
| **`dnssec-keygen`** | `Tạo cặp khóa KSK hoặc ZSK cho DNSSEC` | -a -b -n ZONE | `dnssec-keygen -a RSASHA256 -b 2048 -n ZONE company.com` |
| **`dnssec-signzone`** | `Ký số mã hóa file Zone bằng các khóa ZSK/KSK` | -o domain zonefile | `dnssec-signzone -o company.com db.company.com` |

## 4. 🛠 Thao Tác Thực Chiến & Kịch Bản DevOps (Real-World Scenarios)

### 🛠 Các lệnh thực hành & Cấu hình chuẩn Production:
```bash
# Cấu hình Split-Horizon DNS Views trong named.conf:
view "internal" {
    match-clients { 10.0.0.0/8; 192.168.0.0/16; };
    zone "company.com" { type primary; file "/etc/bind/db.company.internal"; };
};

view "external" {
    match-clients { any; };
    zone "company.com" { type primary; file "/etc/bind/db.company.external"; };
};
```

### 🚀 Kịch bản xử lý sự cố thực tế khi đi làm:
Ký số DNSSEC cho file Zone:
dnssec-signzone -A -3 $(head -c 1000 /dev/urandom | sha1sum | cut -b 1-16) -N INCREMENT -o company.com db.company.com

## 5. 🚀 Bộ Câu Hỏi Phỏng Vấn DevOps & SysAdmin Thực Tế (Interview Q&A)

> **Q: Hai loại khóa mã hóa cốt lõi được sử dụng trong DNSSEC là gì?**  
> **A**: Khóa **ZSK (Zone Signing Key)** dùng ký các bản ghi dữ liệu và khóa **KSK (Key Signing Key)** dùng ký lên ZSK.

> **Q: Tính năng nào của BIND 9 cho phép trả về IP nội bộ cho User trong LAN và trả về IP Public cho User ngoài Internet khi cùng hỏi một tên miền?**  
> **A**: Tính năng **DNS Views (Split-Horizon DNS)**.
