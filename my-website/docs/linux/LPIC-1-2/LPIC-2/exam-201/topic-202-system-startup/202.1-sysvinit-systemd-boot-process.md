# 🐧 Objective 202.1: Tiến Trình Khởi Động SysVinit & Systemd Chuyên Sâu - Bản Chất Hệ Thống LPIC-2 & Thực Chiến DevOps

> 💡 **Bản chất 1 câu**: Phân tích chuyên sâu kiến trúc SysVinit (scripts `/etc/init.d/`, runlevels) vs Systemd (Unit files, cgroups, D-Bus, targets) và Upstart.  
> 🎯 **Trọng tâm phỏng vấn Senior DevOps / SysAdmin**: SysVinit (/etc/init.d/, /etc/inittab, telinit, runlevel), Systemd (/etc/systemd/system/, /lib/systemd/system/, systemctl, systemd-analyze), Upstart.

---

## 1. 🧠 Hình Hình Dung Nhanh (Intuitive Mindset)

SysVinit như xếp hàng mua vé: Từng dịch vụ phải đợi dịch vụ trước chạy xong mới đến lượt (tuần tự, chậm). Systemd như siêu thị tự chọn: Tất cả dịch vụ được khởi chạy song song cùng lúc (Parallel Boot, cực nhanh).

---

## 2. 📚 Lý Thuyết Chuyên Sâu & Bản Chất Hệ Thống (Under The Hood Mechanics - LPIC-2 Official Study Guide)

### 2.2 So Sánh Kiến Trúc SysVinit vs Systemd

| Tiêu chí | SysVinit (Legacy) | Systemd (Modern Standard) |
| :--- | :--- | :--- |
| **Cơ chế khởi động** | Tuần tự từng script (Sequential) | Song song đồng thời (Parallel via Sockets/D-Bus) |
| **File cấu hình** | Shell scripts trong `/etc/init.d/` | Unit files декларативный trong `/lib/systemd/system/` |
| **Quản lý tiến trình** | Theo PID file (dễ bị sót Zombie) | Theo **Linux Control Groups (cgroups)** gom sạch tiến trình con |
| **Quản lý trạng thái** | `/etc/inittab` & Runlevels (0-6) | Target Units (`.target`) & Symlinks |
| **Đo lường thời gian** | Không hỗ trợ | `systemd-analyze blame` soi từng ms |

---

### 2.3 Cấu Trúc File Systemd Service Unit (`.service`)
```ini
[Unit]
Description=My Custom DevOps App
After=network.target postgresql.service

[Service]
Type=simple
User=appuser
ExecStart=/usr/bin/python3 /opt/app/main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## 3. ⚡ Bảng Tra Cứu Câu Lệnh & Cấu Hình Thực Hành (CLI Reference)

| Câu lệnh / Component | Tham số / Option | Giải thích ý nghĩa chi tiết | Ví dụ thực tế trong DevOps / SysAdmin |
| :--- | :--- | :--- | :--- |
| **`systemd-analyze`** | `Phân tích đo lường thời gian boot của từng dịch vụ` | blame, critical-chain | `systemd-analyze blame` |
| **`systemctl`** | `Quản lý các Unit trong Systemd` | status, start, stop, enable | `systemctl status nginx` |
| **`init / telinit`** | `Chuyển đổi runlevel trong SysVinit cổ điển` | 0..6 | `telinit 3` |

## 4. 🛠 Thao Tác Thực Chiến & Kịch Bản DevOps (Real-World Scenarios)

### 🛠 Các lệnh thực hành & Cấu hình chuẩn Production:
```bash
# 1. Tìm các service làm chậm thời gian boot máy chủ:
systemd-analyze blame | head -n 10

# 2. Xem cây phụ thuộc cgroups của tiến trình Docker:
systemctl status docker
```

### 🚀 Kịch bản xử lý sự cố thực tế khi đi làm:
Tối ưu tốc độ khởi động EC2 Instance:
systemd-analyze critical-chain

## 5. 🚀 Bộ Câu Hỏi Phỏng Vấn DevOps & SysAdmin Thực Tế (Interview Q&A)

> **Q: Systemd quản lý và gom nhóm các tiến trình con của một Service bằng công cụ Kernel nào?**  
> **A**: Sử dụng **Linux Control Groups (cgroups)**.

> **Q: Lệnh nào hiển thị danh sách các dịch vụ tốn thời gian khởi động nhất khi boot?**  
> **A**: Lệnh `systemd-analyze blame`.
